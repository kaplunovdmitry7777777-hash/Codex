# Сценарии рисков: каскадное моделирование

Моделировать не один фактор, а **сочетание** неблагоприятных событий и показывать, как одно событие запускает следующее. Результат — не прогноз, а заранее подготовленные действия и пороги срабатывания.

## Чем навык не является

- Не стресс-тест одного допущения (это обычный анализ чувствительности, он входит в отчёт как приложение).
- Не только финансовая модель: последствия описываются для производства, закупок, продаж, персонала, безопасности.
- Не только худший случай: всегда три уровня тяжести.
- Не повод для паралича: на выходе конкретные меры и сигналы.

## Порядок работы (6 шагов)

### 1. Переменные сценария (не более трёх)

Для каждой: что меняется (с числом), вероятность, когда может наступить. Типовые для металлургии:

| Группа | Пример переменной |
|---|---|
| Рынок | Цена арматуры/фасона −10…−20 %; падение спроса строительного сектора |
| Сырьё | Рост цены лома +10…+25 %; дефицит лома зимой; рост засора |
| Энергия | Рост тарифа на электроэнергию/газ; ограничение мощности сетевой компанией |
| Оборудование | Авария узкого места (ДСП, стан) на 2–6 недель; отказ импортного узла без аналога |
| Покупатели | Уход покупателя с долей > 15 % выручки; рост просрочки ДЗ |
| Поставщики | Срыв поставки электродов, огнеупоров, валков; санкционные ограничения на запчасти |
| Люди | Уход ключевых специалистов (сталевары, вальцовщики, главный механик); дефицит кадров |
| Регуляторика и безопасность | Предписание Ростехнадзора с остановкой ОПО; проверка, блокировка счетов |

### 2. Последствия по службам

Для каждой переменной оценить влияние: финансы (EBITDA, деньги, ковенанты), производство (выпуск, загрузка), закупки (запасы, альтернативы), продажи (портфель, цены), персонал (загрузка, сокращения, удержание), безопасность (ОТ, ПБ, экономическая безопасность).

### 3. Каскад (главное)

Показать цепочку, где следствие одного события усиливает другое, и отметить точку, где цепочку можно прервать:

```
ПУСК: падение цены арматуры −12 %
  ↓ Финансы: EBITDA −317 млн/мес, поток после платежей уходит в минус
  ↓ Закупки: снижение закупок лома → поставщики уходят к конкурентам
  ↓ Производство: недогрузка ДСП, рост постоянных затрат на тонну
  ↓ Персонал: простой, риск ухода сталеваров
  ↓ Финансы: рост себестоимости → ещё ниже маржа [вторая волна]
  ✂ Где прервать: кредитная линия + перевод части выпуска в фасон с бо́льшим МД
```

### 4. Матрица тяжести

| Уровень | Определение | Что показывать |
|---|---|---|
| Базовый | Срабатывает один фактор | Влияние на EBITDA, деньги, выпуск; меры |
| Стресс | Два фактора одновременно | То же + срок до недопустимого состояния |
| Тяжёлый | Все факторы, полный каскад | То же + требуются ли решения акционера/СД |

Расчёт: `python3 scripts/scenarnaya_model.py --input scenarii.json --out scenarii.md` (путь относительно папки навыка). Формат JSON описан в начале скрипта: базовая месячная экономика (выпуск, цена, расход и цена лома, электроэнергия, прочие переменные, постоянные, остаток денег, обязательные платежи) и до трёх переменных с относительными изменениями. Скрипт считает все сочетания и чувствительность ±10 %.

### 5. Сигналы раннего предупреждения

Для каждого сценария — измеримый признак, который появляется **до** события:

- Падение цен: снижение биржевых котировок/цен конкурентов 2 недели подряд; рост складских остатков у трейдеров; сокращение портфеля заказов на следующий месяц ниже N т.
- Рост цен на лом: рост экспортных котировок; снижение суточного поступления лома ниже N т; удлинение очереди машин.
- Авария: рост вибрации/температуры подшипников по данным диагностики; повторяющиеся мелкие простои одного узла; остаток критичных запчастей ниже минимума.
- Уход покупателя: снижение заявок > 25 % месяц к месяцу; затягивание оплаты; переговоры покупателя с конкурентом.

### 6. Меры страхования (делать сейчас)

| Мера | Стоимость | Что даёт | Ответственный | Срок |
|---|---|---|---|---|
| Открыть/расширить кредитную линию | % за резерв | Запас ликвидности на N месяцев | ФД | 60 дней |
| Страховой запас критичных запчастей для узкого места | млн руб. в запасах | Сокращение аварийного простоя с недель до суток | Главный механик / МТО | 90 дней |
| Второй поставщик электродов/огнеупоров | Испытания, разница в цене | Нет остановки при срыве поставки | МТО | 2 квартала |
| Ограничение доли одного покупателя < 20 % | Усилия продаж | Снижение зависимости | Коммерческий директор | 2 квартала |
| Удержание ключевых специалистов | Надбавки | Сохранение компетенций в кризис | Директор по персоналу | 30 дней |

## Формат вывода

```
СЦЕНАРИЙ: [название]
Переменные: [A, B, C]
Наиболее вероятный путь: [сочетание и вероятность]

УРОВНИ ТЯЖЕСТИ
Базовый (A): EBITDA …, деньги …, выпуск … — меры: …
Стресс (A+B): … — срок до недопустимого состояния: …
Тяжёлый (A+B+C): … — нужны решения СД: да/нет

КАСКАД
[A → последствие → запуск B → … → итог; где прервать]

СИГНАЛЫ РАННЕГО ПРЕДУПРЕЖДЕНИЯ
- [сигнал → какой сценарий]

МЕРЫ (сделать сейчас)
1. [мера] — стоимость — эффект — ответственный — срок

РЕКОМЕНДАЦИЯ
[один абзац: что делать, в каком порядке, почему]
```

## Правила

- Не больше трёх переменных: сценарий из пяти факторов готовить бессмысленно.
- Всё в числах или диапазонах: «выручка упадёт» не годится, «−320 млн руб. в месяц» годится.
- Не останавливаться на первом шаге: основной ущерб в каскаде.
- Моделировать восстановление, не только удар.
- Отделять «что вероятно» от «что возможно».
- 3–4 сценария за цикл планирования достаточно.
- Вероятности сочетаний скрипт считает как для независимых событий. Связанные факторы (цена проката и цена лома) оценивать вручную.

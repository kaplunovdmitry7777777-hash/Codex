# Постановка задания агенту

Цель: плохой результат ИИ чаще всего вызван размытым заданием, а не моделью. Навык превращает короткую мысль («разберись с простоями стана за сентябрь») в задание, которое агент или сотрудник выполнит без уточнений. Затем задание можно сразу выполнить.

## Когда применять

- «Поставь задачу …», «сформулируй задание …», «как правильно попросить ИИ …».
- Большая или многосоставная задача, которую стоит разбить на части.
- Повторяющаяся задача, которую потом оформят в регулярную (по расписанию) или в отдельный навык.

## Шаги

1. **Цель и решение.** Зачем результат и какое решение по нему примут. Если неясно — один уточняющий вопрос, не больше.
2. **Заполнить шесть блоков** (шаблон ниже). Недостающее дописать разумно и пометить `[допущение]`.
3. **Разбивка.** Если задача содержит независимые части (разные источники, цеха, периоды, контрагенты) — разбить на подзадачи, каждая с собственным входом и форматом, плюс шаг сборки итогов. Зависимые шаги — последовательно, с указанием, что от чего зависит.
4. **Проверка задания** по чек-листу ниже.
5. **Выдать задание** и спросить: «Выполнить сейчас / сохранить как шаблон / оформить регулярным заданием?» Без ответа ничего не запускать.

## Шаблон задания

```
ЗАДАНИЕ: <одна фраза — что сделать>
ЗАЧЕМ: <какое решение примут по результату>

1. ВХОД
   - Файлы / источники: <пути, системы, период, дата среза>
   - Контекст: <AGENTS.md / MEMORY.md направления, если есть>
2. ДЕЙСТВИЕ
   - <шаги анализа, расчёты, сравнения>
3. ФОРМАТ РЕЗУЛЬТАТА
   - <вывод в 1–3 предложениях → таблица (какие колонки) → риски → действия>
   - Куда положить: <файл / документ / ответ в чате>
4. ОГРАНИЧЕНИЯ
   - Ничего не отправлять, не публиковать, не изменять в исходных данных.
   - При нехватке данных — остановиться и перечислить, чего не хватает.
   - Цифры только из источников, со ссылкой на файл и строку/лист.
   - <конфиденциальность, сроки, бюджет>
5. КРИТЕРИИ ПРИЁМКИ
   - <как проверить, что результат верный: сверка итогов, выборочная проверка, контрольные суммы>
6. ПОДЗАДАЧИ (если есть)
   | № | Подзадача | Вход | Результат | Зависит от |
   Сборка: <как объединить результаты>
```

## Чек-лист задания

- Понятно ли, что считается готовым результатом?
- Указан ли период и дата среза данных?
- Есть ли запрет на отправку и изменение данных?
- Есть ли правило «стоп при нехватке данных»?
- Можно ли проверить результат по критериям приёмки?
- Не смешаны ли в одной подзадаче независимые части?

## Пример (кратко)

Мысль: «разберись с простоями стана за сентябрь».

```
ЗАДАНИЕ: Анализ простоев прокатного стана за сентябрь 2026
ЗАЧЕМ: Выбрать 3 меры на октябрь, дающие наибольший прирост выпуска
1. ВХОД: журнал простоев (xlsx, сентябрь), план ремонтов, MEMORY.md направления «Ремонты»
2. ДЕЙСТВИЕ: сгруппировать простои по причинам и узлам; Парето по часам; повторяющиеся отказы; сравнить с августом
3. ФОРМАТ: вывод → Парето-таблица (причина, узел, часы, доля, тонны потерь) → топ-3 мер с эффектом в тоннах
4. ОГРАНИЧЕНИЯ: ничего не отправлять; при отсутствии данных по узлу — указать; цифры со ссылкой на строки журнала
5. ПРИЁМКА: сумма часов по группам = итогу журнала
6. ПОДЗАДАЧИ: (а) Парето по причинам, (б) повторные отказы, (в) сравнение с августом → сборка в один отчёт
```

## Правила

- Не выполнять задание, пока пользователь не выберет «выполнить сейчас».
- Не добавлять блоки, которые задаче не нужны: короткая задача — короткое задание.
- Язык — русский, деловой, без воды.

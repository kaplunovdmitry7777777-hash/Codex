# Улучшатель промптов

Пользователь — генеральный директор металлургического предприятия. Его промпты обычно касаются производства, ремонтов, качества, финансов и экономики, персонала, закупок, продаж, юридических вопросов и безопасности. Ему важны аналитика, точность, наглядность, лаконичность; результаты — на русском.

Задача навыка: взять сырой промпт и вернуть такой, по которому нейросеть с первого раза выдаст результат нужного качества и формата, без выдуманных цифр.

## Почему промпты «не работают»

Модель не знает того, что очевидно автору: какое предприятие, какой цех, какие данные лежат в файле, кто прочитает результат и что с ним будут делать. Она заполняет пробелы догадками — отсюда общие слова, выдуманные цифры и не тот формат. Улучшение промпта — это прежде всего перенос в текст того, что у автора в голове, плюс явные требования к точности и форме результата.

## Порядок работы

### 1. Понять задачу
Определи тип задачи (шаблоны для каждого — в `references/shablony.md`, прочитай нужный раздел):
- анализ данных / таблиц (1С, Excel, выгрузки)
- анализ корпуса документов (договоры, приказы, акты, регламенты)
- отчёт, дашборд, презентация для руководства
- письмо, приказ, служебная записка, ответ контрагенту
- исследование / сравнение вариантов / поиск в интернете
- проверка, расследование, аудит (СБ, КРУ, СМК)
- код, автоматизация, бот
- инструкция для Проекта или системный промпт

Если промпт смешивает несколько задач — разбей на этапы внутри одного промпта или предложи несколько последовательных.

### 2. Диагностика по чек-листу
Оцени исходный промпт по 8 критериям. Для каждого: ✅ есть / ⚠️ частично / ❌ нет.

| # | Критерий | Что проверять |
|---|---|---|
| 1 | Цель | Какое решение будет принято по результату, а не только «что сделать» |
| 2 | Контекст | Предприятие, подразделение, период, оборудование, марки, участники |
| 3 | Входные данные | Какие файлы/источники, где лежат, что в каких колонках, единицы измерения |
| 4 | Роль и уровень | Чьими глазами смотреть (экономист, технолог, юрист, СБ) и для кого результат |
| 5 | Точность | Только из данных, ссылки на файл/лист/строку/пункт, пометка допущений, проверка расчётов |
| 6 | Формат результата | Тип (таблица, HTML-дашборд, Excel, Word, текст в чат), структура, объём, язык |
| 7 | Ограничения | Нормативы (ГОСТ, ТК РФ, 44-ФЗ/223-ФЗ, внутренние СТП), конфиденциальность, что не делать |
| 8 | Критерий готовности | Как понять, что результат хороший; что делать при нехватке данных |

Не все критерии обязательны для каждой задачи: короткому письму не нужен раздел про источники. Отмечай ❌ только там, где пробел реально ухудшит ответ.

### 3. Переписать промпт
Принципы:
- **Сохрани все факты автора** — цифры, названия, сроки, имена файлов. Ничего не выдумывай за него.
- **Пробелы — в квадратные скобки**: `[период: например, январь–сентябрь 2026]`. Автор заполнит сам. Давай пример внутри скобок, чтобы было понятно, что вписать.
- **Структура блоками** (подходит для длинных промптов): Контекст → Задача → Данные → Требования к точности → Формат результата → Ограничения. Для коротких промптов — 3–6 предложений без заголовков.
- **Объясняй зачем**: «Отчёт пойдёт на совет директоров, поэтому главный вывод — в первой строке» работает лучше, чем «ОБЯЗАТЕЛЬНО начни с вывода».
- **Говори, что делать, а не только чего не делать**: «пиши связным текстом» лучше, чем «не используй списки».
- **Требования к точности** для любых аналитических задач: брать цифры только из данных; указывать источник; помечать допущения и оценки; при нехватке данных — сказать, чего не хватает, а не достраивать.
- **Конкретика вместо оценок**: «топ-10 по сумме, порог — отклонение > 5 %» вместо «основные отклонения».
- **Длинный материал — сначала, вопрос — в конце**, если промпт содержит вставленный текст документов.
- **Сложные задачи — план сначала**: попросить модель сначала изложить план и задать до 3 уточняющих вопросов, если от ответа зависит результат.
- **Пример ожидаемого результата** (строка таблицы, абзац, заголовки) — если формат нестандартный.
- Не раздувай. Хороший промпт — самый короткий из тех, что дают нужный результат. Если исходник уже хорош — скажи это и предложи 1–3 точечные правки.

### 4. Ответ пользователю
Используй эту структуру:

**Оценка** — таблица чек-листа (только критерии с ⚠️ и ❌, плюс одна строка «сильные стороны», если они есть).

**Улучшенный промпт** — в блоке кода, чтобы скопировать одним нажатием.

**Что изменено и почему** — 3–6 пунктов, по одной строке.

**Заполните** — список плейсхолдеров `[…]`, если они есть, и до 3 вопросов, ответ на которые заметно улучшит промпт.

Если задача неоднозначна (например, непонятно — нужен дашборд или служебная записка), дай два варианта промпта с подписью, в чём разница, вместо того чтобы угадывать.

Если пользователь просит «просто улучши, без разбора» — отдай только улучшенный промпт.

## Безопасность данных
Если в исходном промпте есть персональные данные (ФИО с паспортными данными, СНИЛС, номера счетов) или явная коммерческая тайна, а промпт, судя по всему, пойдёт во внешний сервис — одной строкой предложи обезличить (например, заменить ФИО табельными номерами). Не навязывай, если данные нужны для задачи.

# Проверка обоснованности выплат: табели Т-13 против проходов КПП

Навык для службы безопасности и внутреннего контроля промышленного предприятия. Выявляет случаи, когда работнику оплачено время, в которое он фактически отсутствовал на территории, считает суммы переплаты и готовит полный пакет документов разбирательства.

## Когда применять

Пользователь даёт папку с табелями учёта рабочего времени (формы Т-13, xlsx/xls), выгрузки проходов через КПП (СКУД) и просит проверить невыходы, опоздания, ранние уходы, переплаты, «кто не выходил, но получил деньги».

## Порядок работы

Строго по этапам, каждый следующий опирается на результат предыдущего. Промежуточные данные сохранять в pickle/parquet в рабочей папке, чтобы не пересчитывать: `recs.pkl` (записи табелей), `blocks.pkl` (суточные блоки), `pay.pkl` (случаи переплаты), `rates.pkl` (ставки), `reg.pkl` (нарушения ведения табеля).

### 1. Регламент

Сначала прочитать регламент учёта рабочего времени предприятия, особенно приложение с перечнем условных обозначений. Из него берутся: какие коды означают оплачиваемое присутствие, какие — неявку, какие детализируют часы явки, какие требуют приказа, как отмечается опоздание. Без регламента классификация кодов будет выдумана — это недопустимо.

Типичная схема (проверять по конкретному регламенту):

- оплачиваемое присутствие: `Я`, `РП`, `РПС`, `ЯО`, `С`, `СО`, `СР`;
- детализация часов явки, отдельно не суммируется: `Н`, `ВЧ`, `РВ`, `ВЧС`, `НЧС`, `НВР`;
- двойная оплата: `РП`, `РПС`, `ЯО`, `С`, `СО`, а также `Я` при наличии `РВ`/`РВС`;
- неявки: `В`, `ОТ`, `Б`, `ДО`, `К`, `ПР` и прочие по приложению;
- опоздание отмечается отдельным кодом (обычно `НЦ`), неподтверждённое отсутствие — отсутствие более 4 часов.

### 2. Разбор табелей

Структура Т-13 в выгрузке 1С: данные начинаются примерно с 15-й строки; A — номер, B — ФИО и должность, C — табельный номер, D–G — коды с днями и часами, H–J — неявки, K–AO — дни месяца 1–31. Блок одного работника занимает 5, 7 или 9 строк в зависимости от числа видов оплаты. Подразделение, табельная группа, месяц и организация читаются из шапки листа.

Порядок: открыть один файл, определить структуру, затем скриптом проверить остальные на совпадение структуры и вывести только список отклонений. Не выводить в чат большие таблицы — только итоговые числа и количество аномалий.

Собрать единый реестр записей: организация, подразделение, код подразделения, табельная группа, месяц, таб. №, ФИО, должность, по каждому дню — код и часы.

### 3. Разбор проходов КПП

Нормализовать ФИО (регистр, ё/е, двойные пробелы), сопоставить с работниками табеля. Неоднозначные совпадения (несколько работников с одинаковым ФИО) исключать из расчёта и выносить в отдельный список. Отбросить недостоверные строки (пустые даты, проходы без пары, служебные записи).

Обязательно проверить границы выгрузки: первые и последние сутки периода, дни с разрывом данных. Такие сутки исключать из расчёта и фиксировать в методике.

### 4. Суточные блоки и сопоставление

Сравнение ведётся по суткам, а не по календарным датам. Сутки, связанные ночной сменой (выход после полуночи следующего дня), объединяются в один блок алгоритмом union-find; отсечка в 24:00. Для блока считаются:

- `pres` — оплаченные часы по табелю, отдельно одинарные и двойные;
- `terr` — фактическое время на территории: от первого входа до последнего выхода в пределах блока;
- `short = max(0, pres - terr - допуск)`.

Допуск 2 часа: дорога от проходной до рабочего места, переодевание, душ. Допуск согласовать с пользователем, он влияет на все результаты.

### 5. Классификация

| Код | Смысл |
|---|---|
| П1 | Опоздание или ранний уход: на территории меньше оплаченного |
| П2 | Невыход: в табеле явка, проходов в этот день нет |
| П3 | Невыход: ни одного прохода за весь период при начисленной оплате |

Отдельно фиксировать нарушения ведения табеля: отметка отпуска или больничного при нахождении на территории; работа в выходной день без приказа; присутствие превышает оплаченное более чем на 4 часа; пустой код при наличии проходов; коды, отсутствующие в приложении регламента; опоздания без кода `НЦ`.

Для П2 проверять примыкание к периоду нетрудоспособности (±1 день от кода `Б`) и помечать такие случаи — они требуют сверки с листком нетрудоспособности, а не обвинения.

### 6. Деньги

Из справочника ставок брать часовую ставку. Уточнить, одинарная она или двойная: часто в справочнике хранится двойная, тогда одинарная = ставка / 2. Сумма = неподтверждённые одинарные часы × одинарная ставка + неподтверждённые двойные часы × двойная ставка.

Работникам без ставки суммы не придумывать: писать «ставка не определена, сумма подлежит расчёту расчётным отделом». Для ранжирования допустима оценка по медиане ставки подразделения, но в отчётах оценочные суммы всегда помечать отдельно от подтверждённых.

### 7. Результаты

Выдавать отчёты в xlsx, не вываливать таблицы в чат:

- сводный табель за период: листы по месяцам, сводка по подразделениям, динамика, аномалии; итоги формулами SUMIF/COUNTIF;
- отчёт по сверке: лист-дашборд с кликабельными ссылками, листы по видам нарушений, по подразделениям, по работникам, детализация по дням со временем входа и выхода;
- отчёт о переплате: часы и суммы, наиболее серьёзные записи к проверке, потенциальная переплата по подразделениям, случаи без ставки;
- пояснительная записка для руководства на 2–3 страницы в docx;
- при необходимости интерактивный HTML-дашборд: часы и рубли рядом, фильтры по подразделению, месяцу, виду нарушения.

## Документы разбирательства

### Опросные листы

По запросу готовить отдельный документ на каждого работника и на каждого специалиста отдела организации труда и заработной платы (ОТиЗ), ведущего табель. Оформление по ГОСТ Р 7.0.97-2016: поля левое 20 мм, правое 10 мм, верхнее и нижнее 20 мм; Times New Roman 12–14; абзацный отступ 1,25 см; выравнивание по ширине; номер страницы сверху по центру начиная со второй страницы; реквизиты — организация, вид документа, дата, номер, место составления, заголовок, текст, подписи, отметка об исполнителе; гриф «Конфиденциально» и «Экз. №» справа вверху.

Содержание листа работника: сведения об опрашиваемом (ФИО, таб. №, должность, подразделение, участок, специалист ОТиЗ, ведущий табель); основание проверки; таблица расхождений по видам с часами и суммами; разъяснение прав (ст. 193 ТК РФ — два рабочих дня на объяснение, ст. 51 Конституции РФ); блоки вопросов — общие (режим работы, пропуск, проходы без регистрации, работа вне территории, кто передаёт сведения о явке) и по виду нарушения (конкретные даты невыходов, время входа и выхода при опозданиях, весь период при П3); вопросы о двойной оплате и о больничных, если они есть; подписи; приложение в альбомной ориентации — перечень всех случаев по дням с графой «Пояснение работника».

Содержание листа специалиста ОТиЗ: курируемые подразделения и участки; сводные цифры по ним; работники из перечня опрашиваемых в его зоне; вопросы о порядке получения первичных сведений о явке, об использовании данных СКУД, о подписании табелей, по каждому конкретному работнику, о нарушениях регламента (код опоздания, работа в выходные без приказа, коды вне приложения, двойная оплата), о давлении со стороны руководителей подразделений и о конфликте интересов.

Тон нейтральный: расхождение — основание для проверки, а не доказанный факт вины. Прямо писать, что возможны законные объяснения (командировка, работа вне территории, неисправность турникета).

### Отбор опрашиваемых

Если нужен топ-N работников, ранжировать по сумме мест: место по неподтверждённым часам плюс место по сумме переплаты. Так в выборку попадают и крупные суммы, и крупные объёмы времени.

### Адресаты рассылки

Из кадрового списка работников строить цепочку руководителей по развёрнутому наименованию подразделения: непосредственный (младший) руководитель — мастер, старший мастер, начальник смены своего участка; прямой (старший) — начальник участка, затем начальник цеха или отдела с заместителем. Если на участке руководителя нет, подниматься к главе цеха, но не подставлять мастеров чужих участков. Отдельно выносить случаи, требующие уточнения: уволенные работники, работники другой организации, смена фамилии, отсутствие адреса электронной почты, работник сам является руководителем.

Выдавать два файла: рабочий xlsx с фильтрами (листы «Адресаты», «По руководителям», «Особые случаи», «Порядок рассылки») и docx по ГОСТ на подпись.

### Выписки

Для удобства опроса готовить отдельные выписки по каждому подразделению и по каждому куратору ОТиЗ: сводка, работники, случаи по дням, нарушения ведения табеля. Принцип: каждый адресат получает только свой срез. Полные отчёты и сводный табель со всеми персональными данными не рассылать за пределы службы безопасности, ОТиЗ и руководства. Работнику достаточно его опросного листа с приложением.

## Технические примечания

- openpyxl: внутренние ссылки между листами делать только через `Hyperlink(ref=..., location="'Лист'!A1")`, иначе ссылка сохранится как внешняя и перестанет работать.
- Нельзя записывать значение в объединённую ячейку: задавать только `.border`.
- Формулы пересчитывать через LibreOffice (`soffice --headless --convert-to xlsx`), иначе получатель увидит пустые итоги.
- Документы Word удобно собирать через docx-js (Node): таблицы с `cantSplit`, `keepNext` для заголовков и блока подписей, линии для ответов — абзацы с правым табстопом и подчёркнутым заполнителем, а не несколько абзацев с нижней границей (Word склеит их в одну линию).
- Проверка результата обязательна: рендерить docx в pdf и просматривать страницы, сверять итоговые числа документов с исходным датафреймом программно.
- Контрольная сверка: сумма случаев по подразделениям, по кураторам и по видам нарушений должна совпадать с общим числом.

## Чего не делать

- Не называть расхождение доказанным хищением или неподтверждённое отсутствиеом: это основание для проверки.
- Не придумывать суммы при отсутствующей ставке.
- Не включать в расчёт сутки с заведомо неполной выгрузкой СКУД.
- Не рассылать массивы персональных данных шире необходимого.
- Не выводить в чат большие таблицы: только итоги, числа аномалий и ссылки на файлы.

Расхождение СКУД и табеля — предварительный флаг, а не дисциплинарный вывод. Подтверди исключения и результат с кадровой службой. Для XLSX через openpyxl записывай английские имена функций и запятые. Используй только собственный локальный кеш; не загружай pickle из источников.

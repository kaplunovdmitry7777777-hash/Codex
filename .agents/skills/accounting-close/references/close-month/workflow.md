Правила основного файла навыка имеют приоритет над примерами. Если пример предполагает конкретный путь, версию библиотеки или приложение, проверь доступный аналог.

Запустите workflow закрытия месяца. Сверьте данные, флагайте расхождения,
опишите отчёт о прибылях простым языком и выгрузите пакет закрытия для
архива владельца (и его бухгалтера).

Разбор аргументов:
- `--month` (по умолчанию — предыдущий календарный месяц) — формат `YYYY-MM`
- `--save-to` (по умолчанию `папка`) — `папка` (рабочая папка бизнеса),
  `desktop` (локально, вне папки проекта) или `both`

## Шаг 1 — Сверка

Запустите workflow навыка `month-end-prep`:

1. Загрузите все операции из 1С и банковской выписки за целевой месяц.
2. Загрузите поступления от каждого подключённого канала (ЮKassa,
   банковский эквайринг) за тот же месяц.
3. Сопоставьте операции 1С/выписки с поступлениями канала по сумме и дате
   (±2 дня).
4. Выведите три категории расхождений:
   - **Несопоставленные поступления канала** — деньги пришли через
     ЮKassa/эквайринг, но не отразились ни в выписке, ни в 1С
   - **Несопоставленные приходы 1С/выписки** — 1С или выписка показывают
     доход без записи в канале (наличные? перевод? неверно разнесено?)
   - **Строки с расхождением** — сопоставлены, но сумма отличается
     (комиссии, частичные возвраты)

## Шаг 2 — Флагать подозрительные операции

Выведите в том же отчёте:
- **Неразнесённые операции** — записи в 1С без категории
- **Подозрительные дубли** — та же сумма, тот же контрагент, в пределах
  3 дней
- **Недостающие чеки/акты** — операции в 1С свыше 5 000 ₽ (порог
  настраивается) без прикреплённого документа

Для каждой предложите действие: разнести как X, удалить дубль, прикрепить
чек/акт из входящих.

Дождитесь, пока владелец разберёт флагнутые пункты, прежде чем формировать
текст отчёта. Не разносите категории и не удаляйте дубли автоматически.

## Шаг 3 — Отчёт о прибылях простым языком

После разбора флагов сформируйте отчёт о прибылях простым языком:

```
{Месяц ГГГГ} закрылся с выручкой {выручка} ₽ ({+/-}{X}% к прошлому месяцу).
Главный драйвер: {категория/клиент}. Самое сильное движение: {категория}
{направление} на {сумма} ₽, потому что {причина, выведенная из операций}.

Маржа: {X}% ({+/-}Y п.п. к прошлому месяцу). {Комментарий по расходной части}.

Три заметных момента:
1. ...
2. ...
3. ...
```

Цифры берутся из 1С/выписки; *почему* — из сопоставления крупных операций,
имён контрагентов и дельты к прошлому месяцу.

## Шаг 4 — Выгрузить пакет закрытия

Сформируйте два файла:

1. **`close-packet-{YYYY-MM}.xlsx`** — книга с несколькими листами:
   - `Сверка` — таблица сопоставления 1С/выписки ↔ канал с подсвеченными
     расхождениями
   - `Флаги` — неразнесённые / дубли / недостающие чеки-акты
   - `Отчёт о прибылях` — отформатированный отчёт с колонкой дельты к
     прошлому месяцу
   - `Оборотка` — счета учёта и остатки на конец месяца
2. **`close-packet-{YYYY-MM}.pdf`** — однострочный обзор: отчёт о прибылях
   + ключевые цифры + количество расхождений

Сохраните оба файла в выбранное `--save-to` расположение. Формат имени:
`close-packet-2026-04.xlsx` и т.д.

## Сбои источников

Если 1С/выписка недоступны — остановитесь: сверка требует их как источник
истины. Если канал (ЮKassa, банковский эквайринг) недоступен — проведите
сверку по доступным каналам и отметьте «ЮKassa не подключена — поступления
ЮKassa исключены из сверки» (или какой канал недоступен). Если недоступны
все каналы — проведите анализ только по 1С/выписке и отметьте это отдельно.

## Гейты одобрения

- **Никогда не исправляйте флагнутые пункты автоматически.** Всегда
  показывайте расхождение, предлагайте действие, ждите владельца.
- **Никогда не удаляйте дубли без явного подтверждения.** Показывайте обе
  записи рядом.
- **Сохранение пакета — автоматическое** — файл уходит в собственное
  хранилище владельца.

## Результат

Завершите работу коротким резюме на один абзац: выручка, маржа, количество
оставшихся расхождений (если есть), пути к сохранённому пакету. Если не
все расхождения разрешены — перечислите их, чтобы владелец мог вернуться к
ним.

## ЮKassa

### Структура отчёта о поступлениях

Коннектор или выгрузка ЮKassa возвращает список платежей и итог по выплате
(поступлению на расчётный счёт). Ключевые поля:

| Поле | Заметки |
|---|---|
| `id` | Идентификатор платежа в ЮKassa |
| `created_at` | Когда прошёл платёж |
| `amount.value` | Валовая сумма платежа (то, что заплатил клиент) |
| `income_amount.value` | Сумма к зачислению за вычетом комиссии ЮKassa |
| `status` | Используйте только `succeeded` (и `waiting_for_capture`, если работаете с холдированием) |
| `payment_method.type` | Способ оплаты — карта, СБП и т.д., полезно для сверки |

**Дата зачисления vs дата платежа:** ЮKassa зачисляет деньги на расчётный
счёт не сразу — платёж от 28 апреля может попасть в банковскую выписку
только 2 мая. Сверяйте по **дате зачисления** (из банковской выписки), а не
по дате платежа.

**Возвраты:** отображаются отдельной операцией со статусом `refunded` или
отрицательной суммой. Они должны компенсировать исходный платёж — не
флагайте возврат как расхождение против банковской выписки, если в 1С нет
встречной операции возврата.

**Комиссия:** стандартная комиссия ЮKassa — около 3,5–6% в зависимости от
тарифа и способа оплаты (порог настраивается — уточните свой тариф). Именно
на эту величину `income_amount` меньше `amount`.

## Банковский эквайринг

### Структура отчёта о поступлениях

Банковский эквайринг (Сбербанк, Т-Банк, Альфа-Банк и другие) обычно
называет это **реестром платежей** или **выпиской по эквайрингу**. Одна
выгрузка покрывает 1–2 рабочих дня продаж.

Ключевые поля:

| Поле | Заметки |
|---|---|
| Номер операции / RRN | Идентификатор транзакции |
| Дата зачисления | Дата, когда деньги пришли на расчётный счёт |
| Сумма к зачислению | Чистая сумма (уже за вычетом комиссии эквайринга) |
| Статус | Используйте только успешные / проведённые операции |

**Комиссия:** банк удерживает комиссию до зачисления — обычно 1,5–2,5%
(порог настраивается — уточните свой тариф). Сумма к зачислению уже чистая;
сравнивайте её с приходом в банковской выписке, а не с валовой суммой чека.

**Скорость зачисления:** по умолчанию — на следующий рабочий день; у
некоторых банков есть услуга ускоренного зачисления день в день.

## Логика сверки (все каналы приёма платежей)

Используйте эту логику, чтобы сопоставить поступления ЮKassa/эквайринга с
приходом в банковской выписке:

```
для каждого поступления ЮKassa/эквайринга за целевой месяц:
    искать строку в банковской выписке, где:
        abs(сумма_выписки - income_amount) < 50 ₽
        И abs(дата_выписки - дата_зачисления) <= 2 дня

    если совпадение найдено:
        пометить как СВЕРЕНО
    иначе если abs(сумма_выписки - income_amount) < 50 ₽ (расходится только дата):
        флагать как РАСХОЖДЕНИЕ_ПО_ДАТЕ (обычно просто разница в сроках — низкий приоритет)
    иначе если поступление вообще не найдено в выписке:
        флагать как НЕТ_В_ВЫПИСКЕ
    иначе если строка выписки не сопоставлена ни с одним поступлением:
        флагать как ПРИХОД_БЕЗ_ИСТОЧНИКА (может быть перевод по номеру телефона, наличные, другой доход)
```

**Бизнес с несколькими каналами приёма платежей:** прогоняйте эту логику
отдельно по ЮKassa и по каждому банку-эквайеру, затем объединяйте флаги.
Строка в выписке, не сопоставленная с ЮKassa, может законно быть выплатой
от другого эквайера — не флагайте её, пока не проверили все подключённые
каналы.

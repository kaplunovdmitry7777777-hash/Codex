Правила основного файла навыка имеют приоритет над примерами. Если пример предполагает конкретный путь, версию библиотеки или приложение, проверь доступный аналог.

Запустите приоритизацию лидов. Просканируйте воронку, ранжируйте по срочности и потенциалу, подтяните контекст из переписки и подготовьте владельца к звонкам.

Разбор аргументов:
- `--n` (по умолчанию: `5`) — сколько лидов показать (1–10)
- `--date` (по умолчанию: сегодня) — дата, на которую собирается список (`YYYY-MM-DD`)

## Шаг 1 — Скан воронки

По логике скилла `lead-triage`:

1. Получить открытые лиды/сделки из Битрикс24 (MCP) с активностью за последние 30 дней. Если Битрикс24 недоступен — взять выгрузку CRM из папки (`crm_клиенты.csv`, подходит и самописная CRM).
2. Подтянуть переписку из Gmail по каждому лиду (последние 3 письма на контакт).
3. Оценить каждый лид по:
   - **Недавность**: сколько дней с последнего касания владельца (меньше = лучше)
   - **Стадия**: насколько близко к закрытию (более поздняя стадия = выше приоритет)
   - **Сигнал**: недавняя входящая активность (открытие письма, ответ, встреча в календаре, визит на сайт)
   - **Сумма**: размер сделки из Битрикс24 (или CSV-выгрузки)

## Шаг 2 — Ранжировать и выбрать топ N

Ранжируйте все оценённые лиды и выберите топ `--n`. При равенстве баллов — приоритет лидам с неотвеченными входящими сигналами.

Для каждого выбранного лида — карточка звонка:

```
{Ранг}. {Имя контакта} — {Компания}
Сделка: {сумма} ₽ | Стадия: {стадия} | Последний контакт: {X дней назад}
Сигнал: {последняя активность}

ТЕЗИСЫ РАЗГОВОРА
• {тезис из переписки/контекста сделки}
• {тезис из переписки/контекста сделки}
• {открытый вопрос, который стоит задать}

ЦЕЛЬ ЗВОНКА: {одно предложение — перевести на следующую стадию / реанимировать / закрыть}
```

## Шаг 3 — Блок в календаре (если подключён)

Для каждого лида в списке предложите заблокировать 20 минут в календаре владельца на выбранную дату.

Покажите предлагаемые записи:
```
{временной слот} — Звонок: {Имя контакта} ({Компания})
```

Дождитесь подтверждения владельца, какие звонки блокировать, прежде чем создавать события.

**Если календарь не подключён** — пропустите этот шаг и просто отдайте список на обзвон по порядку приоритета, отметив «календарь не подключён — звоните по списку сверху вниз».

## Шаг 4 — Черновики писем

Для каждого лида с неотвеченным письмом старше 3 дней подготовьте короткий черновик:
```
Тема: Re: {тема переписки}

Здравствуйте, {имя}.

{Одно предложение со ссылкой на предыдущий разговор}. {Одно предложение с чётким следующим шагом или вопросом}.

{Подпись}
```

## Сбои коннекторов

Если Битрикс24 недоступен и нет выгрузки CRM в папке — остановитесь и сообщите владельцу: скоринг лидов требует данных CRM. Если Gmail недоступен — пропустите Шаг 4 (контекст переписки и черновики) и отметьте в выводе «Gmail не подключён — контекст переписки и черновики писем пропущены». Если календарь недоступен — пропустите блокировку времени и отметьте это.

## Границы одобрения

- **Никогда не отправлять письма автоматически.** Только показывать черновики на одобрение владельца.
- **Никогда не создавать блоки в календаре без подтверждения владельца** — сначала показать предложенный список.
- **Никогда не менять стадии сделок в Битрикс24 автоматически.**

## Вывод

Покажите ранжированный список на обзвон с тезисами. Затем покажите предложенные блоки календаря (если подключён) и попросите подтверждение. Затем покажите черновики писем и спросите, что отправлять.

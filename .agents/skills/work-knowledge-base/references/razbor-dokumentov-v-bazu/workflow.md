# Разбор документов в базу знаний

Цель: держать базу из сотен и тысяч документов предприятия в порядке, чтобы ответы ИИ по ней были точными, со ссылками на источник, и не требовали каждый раз перечитывать всё. Документ обрабатывается один раз; дальше работа идёт с каталогом, индексами и короткими карточками.

## Когда применять

- «Разбери новые документы», «добавь в базу», «залил папку в raw».
- «Ревизия базы», «найди дубли», «что устарело».
- «Найди в базе …», «что у нас есть по …».
- Создание базы с нуля.

## Структура

```
База/
├── _правила.md           # темы, типы документов, словарь, конфиденциальность
├── каталог.csv            # одна строка = один документ (главный файл базы)
├── index.md                # карта базы: темы → ссылки на их index.md, число документов
├── raw/                    # входящие как есть; ничего не править и не удалять
├── text/                   # текстовая версия каждого документа: <ID>.md, таблицы — <ID>_<лист>.csv
├── wiki/
│   └── <тема>/
│       ├── index.md        # список карточек темы с однострочным описанием
│       └── <ID>.md         # карточка документа
└── _отчёты/ГГГГ-ММ-ДД_разбор.md
```

Темы по умолчанию (правятся в `_правила.md`): производство, оборудование-и-ремонты, технология, качество, промбезопасность-и-охрана-труда, закупки, продажи, финансы, персонал-и-оплата, юридическое, безопасность, распорядительные-документы.

### Колонки каталога

`ID; файл_raw; хэш; формат; тема; тип_документа; название; номер; дата_документа; стороны_или_подразделение; ключевые_слова; статус; действует_до; заменяет_ID; конфиденциально; качество_текста; дата_разбора`

Разделитель — «;», кодировка UTF-8 с BOM (чтобы корректно открывалось в Excel). ID — `Д-000001` по порядку, не меняется никогда.

### Статусы

| Статус | Значение |
|---|---|
| `new` | Файл в raw/, ещё не разобран |
| `processed` | Есть текст и карточка |
| `duplicate` | Тот же хэш или тот же номер+дата+тип, что у другого ID; карточка не создаётся |
| `update_needed` | Появилась новая редакция, истёк срок действия или карточка противоречит другой |
| `superseded` | Заменён документом из `заменяет_ID`; в ответах не используется без оговорки |
| `unreadable` | Текст не извлечён или распознан плохо; нужен человек |

## Режим 1. Разбор новых документов

1. **Прочитать** `_правила.md` и `каталог.csv`. Нет базы — создать структуру и спросить о темах (можно взять темы по умолчанию).
2. **Найти новое:** файлы в raw/, чьего хэша (SHA-256) нет в каталоге. Делать это скриптом, а не чтением файлов.
3. **Партия.** Больше 50 новых — работать партиями по 30–50, прогресс сохранять в каталог после каждой. Прервались — продолжить со статуса `new`.
4. **Извлечь текст** в `text/<ID>.md` (скриптом, пакетно):
   - docx, doc, rtf, odt → markdown (pandoc / markitdown / LibreOffice).
   - xlsx, xls, csv → каждый лист в отдельный CSV + в `<ID>.md` список листов, заголовки, число строк, первые 5 строк.
   - pdf с текстом → текст по страницам с метками `[с. N]`.
   - сканы (pdf без текста, jpg, png, tif) → OCR с русским языком (tesseract `rus+eng`); при плохом результате — посмотреть изображение самому.
   - В `качество_текста` писать: `текст` / `ocr-хорошо` / `ocr-плохо`. Ничего не извлечено — статус `unreadable`.
5. **Проверить дубли:** тот же хэш → `duplicate`; тот же тип+номер+дата при разном хэше → сравнить текст: совпадает → `duplicate`, отличается → новая редакция (старой — `superseded` и `заменяет_ID`).
6. **Карточка** `wiki/<тема>/<ID>.md` по шаблону ниже. Только факты из текста документа; сомнительное помечать `[проверить]`.
7. **Обновить** строку в каталоге, `wiki/<тема>/index.md` и корневой `index.md`.
8. **Отчёт** `_отчёты/<дата>_разбор.md` и коротко в чат: сколько принято по темам, дубли, новые редакции, `unreadable` списком, документы с истекающим сроком (ближайшие 90 дней).

### Шаблон карточки

```markdown
---
id: Д-000123
тип: приказ | договор | акт | регламент | инструкция | отчёт | письмо | реестр | …
номер: …
дата: ГГГГ-ММ-ДД
действует_до: …
стороны: …
источник: raw/… ; текст: text/Д-000123.md
статус: processed
---
# <Название>

**Суть (2–3 предложения):** …

**Ключевые положения** (со ссылкой на пункт или страницу):
- … [п. 3.2]

**Цифры, сроки, суммы, ответственные:** …

**Связи:** заменяет / ссылается на / связан с [[Д-000045]]

**Ключевые слова:** … (включая заводские сокращения и синонимы)
```

Карточка — не длиннее ~40 строк. Полный текст остаётся в text/.

## Режим 2. Поиск и ответы по базе

Порядок, экономящий токены:
1. Отфильтровать `каталог.csv` скриптом (тема, тип, даты, ключевые слова, статус ≠ duplicate/superseded).
2. Поиск по text/ и wiki/ через grep/ripgrep с синонимами и сокращениями из `_правила.md`.
3. Прочитать карточки найденного (до 10); в полный текст — только за нужными пунктами.
4. Ответ: вывод → факты со ссылкой `[Д-000123, п. 3.2]` → чего в базе нет. Документы `superseded` и с истёкшим сроком — только с оговоркой.
5. Не нашлось — так и сказать, не достраивать ответ из общих знаний без пометки.

## Режим 3. Ревизия базы

Отчёт GREEN / YELLOW / RED, только чтение:
- файлы в raw/ без строки в каталоге и строки без файла;
- карточки без текста и наоборот;
- `unreadable` и `ocr-плохо` — список на доработку;
- сроки действия истекли или истекают в 90 дней;
- противоречия между действующими документами одной темы;
- темы, разросшиеся больше 200 карточек (предложить разделить).
Исправления — списком, выполнять после подтверждения.

## Правила

- raw/ неприкосновенна: не переименовывать, не править, не удалять. Дубли только помечать.
- Массовую работу (хэши, извлечение текста, фильтр каталога) делать скриптами; читать самому только то, что нужно для карточки или ответа.
- Работать с файлами там, где они лежат (в подключённой папке на компьютере пользователя), не копировать базу целиком.
- Конфиденциальное (персональные данные, зарплаты, СБ) помечать в каталоге; в карточки не переносить паспортные данные, номера счетов и карт.
- Ничего не отправлять и не публиковать из базы.
- База выросла за ~3000 документов или поиск grep часто промахивается — предложить добавить поисковый индекс (полнотекстовый SQLite FTS5 или векторный) поверх text/; структура базы при этом не меняется.
- Язык — русский, деловой, коротко.

# Прогноз кассы (Cash Flow Snapshot)

Строит прогноз кассы на 30/60/90 дней с доверительными интервалами по проценту
отклонения и именованными риск-флагами. Отдаёт вывод из двух частей: короткую
сводку в чат и скачиваемую XLSX-книгу.

**Быстрый старт**

> «Хватит ли денег на зарплату в следующем месяце?»

ассистент берёт дебиторку/кредиторку и постоянные расходы из доступных
источников, считает ожидаемые поступления и расходы на окна 30, 60 и 90 дней,
применяет доверительные интервалы на основе исторического разброса платежей
каждого контрагента и называет конкретные риски по именам.

---

## Рабочий процесс

### Шаг 1 — Определить доступные источники данных

Проверьте, какие файлы есть в рабочей папке бизнеса. Пробуйте в этом порядке:

1. Банковская выписка — основной источник по дебиторке/кредиторке, остаткам и
   постоянным расходам (видны как регулярные операции)
2. 1С — выгрузка продаж и расходов
3. ЮKassa / эквайринг — история платежей и тайминги зачисления
4. CSV-загрузка — общий fallback, если ни один файл не подходит под ожидаемый
   формат

Если подходящего файла нет и ничего не приложено, попросите пользователя
выгрузить нужный отчёт или загрузить CSV (табличные данные приход/расход,
любой разумный формат). Отметьте в выводе, какие источники использовались —
это влияет на ширину доверительного интервала.

### Шаг 2 — Забрать данные

**Из банковской выписки:**
- Дебиторка/кредиторка: контрагент, сумма, дата счёта/операции, срок оплаты,
  дней просрочки (если отдельного отчёта по дебиторке нет — берите из
  `счета_дебиторка.csv`)
- Повторяющиеся постоянные расходы: аренда, зарплата, подписки (ищите
  регулярные операции с одинаковым контрагентом и суммой)

**Из 1С (выгрузка продаж/расходов):**
- Продажи: контрагент, сумма, дата
- Расходы: статья/поставщик, сумма, дата
- Ищите повторяющиеся статьи расходов — это и есть постоянные расходы

**Из ЮKassa / эквайринга:**
- История платежей: дата операции, сумма, дата зачисления
- Используйте лаг зачисления (дата операции → дата зачисления), чтобы
  посчитать среднее и разброс по каждому контрагенту или типу операции

**Из CSV-загрузки:**
- Разбирайте как табличные данные приход/расход
- Требуемые колонки (гибко по названию): дата, сумма, тип (приход или
  расход), описание
- Если колонки неоднозначны — покажите строку заголовков и попросите
  подтвердить сопоставление

### Шаг 3 — Посчитать исторические тайминги платежей

Для каждого контрагента по дебиторке (или источника дохода из CSV) посчитайте:
- **Средний лаг платежа** — среднее число дней от даты счёта/операции до
  поступления
- **Разброс платежей** — стандартное отклонение лага платежа за последние
  6–12 платежей
- Используйте разброс, чтобы задать ширину доверительного интервала (см.
  Шаг 4)

Если по контрагенту меньше 3 платежей, используйте среднее по всей выборке
как точечную оценку и применяйте интервал ±30% по умолчанию. При работе с
данными CSV, где истории достаточно (≥3 платежей на источник), считайте
интервал из фактического разброса платежей — не берите ±30% по умолчанию.

### Шаг 4 — Построить прогноз на 30/60/90 дней

Постройте три временных окна: 0–30, 31–60 и 61–90 дней.

Для каждого окна посчитайте:

| Строка | Метод |
|---|---|
| Ожидаемые поступления | Дебиторка со сроком в этом окне, скорректированная на средний лаг платежа |
| Ожидаемые расходы | Кредиторка со сроком в этом окне + постоянные расходы, попадающие в это окно |
| Чистая позиция по кассе | Поступления − Расходы |
| Доверительный интервал | ± средневзвешенный разброс платежей в % от ожидаемых поступлений |

Формула доверительного интервала:
```
band_pct = weighted_avg_stddev_days / avg_payment_lag_days
low  = net_cash × (1 − band_pct)
high = net_cash × (1 + band_pct)
```

Округляйте `band_pct` до одного знака после запятой. Ограничивайте ±50% —
более высокий разброс означает, что данных слишком мало для модели; в этом
случае отметьте риск (см. Шаг 5) вместо того, чтобы моделировать интервал.

### Шаг 5 — Отметить именованные риски

Проверьте условия, которые уводят нижнюю границу прогноза в минус или
создают риск нехватки ликвидности. Для каждого найденного риска сформируйте
флаг в одну строку:

- **Риск позднего плательщика:** «ООО „Ромашка“ обычно платит с опозданием
  на 18 дней; это сдвигает их счёт на 420 000 ₽ из окна 0–30 дней на 48-й
  день.»
- **Кассовый разрыв по зарплате:** «Зарплата (1 100 000 ₽) выплачивается
  15 апреля. Остаток по нижней границе на 14 апреля: 960 000 ₽. Риск
  нехватки: 140 000 ₽.»
- **Предупреждение о нехватке данных:** «По контрагенту Y всего 2 платежа в
  истории — доверительный интервал по умолчанию ±30%.»
- **Предупреждение об источнике:** «Работаем только на данных из
  CSV-загрузки — нет банковской выписки или 1С с актуальными данными по
  кредиторке или постоянным расходам. Доверительные интервалы шире обычного.»

Ограничьтесь топ-5 рисков по серьёзности (сначала — с наибольшим влиянием в
рублях).

### Шаг 6 — Выдать результат

**Сводка в чат** (всегда):
```
Прогноз кассы — [диапазон дат]
Источник(и): [использованные источники]

              Ожидаемо    Низкая    Высокая
0–30 дней:    X XXX ₽     X XXX ₽   X XXX ₽
31–60 дней:   X XXX ₽     X XXX ₽   X XXX ₽
61–90 дней:   X XXX ₽     X XXX ₽   X XXX ₽

⚠ Отмечено рисков: [count]
  • [риск 1]
  • [риск 2]
  ...
```

**XLSX-книга** (всегда):
Прочитайте `xlsx/SKILL.md` перед генерацией. Сделайте книгу с тремя листами:

1. **Свод** — таблица прогноза 30/60/90 с доверительными интервалами. Под
   каждой строкой окна разверните встроенные подстроки с отдельными
   операциями, из которых складываются поступления (зелёным) и расходы
   (красным). Это делает оценки проверяемыми без ухода со листа «Свод».

2. **Детали** — все операции, сгруппированные по окнам, отсортированные по
   дате внутри каждой группы. Добавьте колонку нарастающего итога
   (накопленные поступления минус расходы внутри окна) и строку
   промежуточного итога внизу каждого окна с суммой поступлений, расходов и
   чистым потоком. Прошедшие операции вынесите серым в отдельный раздел
   внизу для справки. Убедитесь, что у всех трёх окон есть строки, даже если
   одно из них пустое — покажите строку-заглушку «Нет операций в этом окне».

3. **Риски** — отмеченные риски с влиянием в рублях и затронутым окном.

Сохраните как `cash-flow-snapshot-[YYYY-MM-DD].xlsx`.

---

## Гейты подтверждения

Нет деструктивных действий — этот навык только читает данные. Гейт
подтверждения перед генерацией прогноза не требуется.

После выдачи результата напомните пользователю:
> «Этот прогноз построен на данных [перечисленные источники]. Он не заменяет
> бухгалтерскую консультацию — сверьте с бухгалтером перед принятием решений
> о финансировании.»

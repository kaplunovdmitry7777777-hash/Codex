# Margin Analyzer — анализ маржи и юнит-экономики

> **Статус:** MVP-черновик · **Владелец:** JJ · **Версия:** 1.1.0
> **Категория:** Финансы и операции · **Фаза:** V2

## Быстрый старт

Когда владелец малого бизнеса спрашивает «стоит поднять цены?» или «у меня нормальная маржа?», этот навык:

1. **Определяет объём анализа** — какие товары/услуги в фокусе
2. **Забирает данные о себестоимости** из банковской выписки / выгрузки 1С (себестоимость, прямые расходы)
3. **Забирает данные о выручке** из выгрузки продаж 1С / ЮKassa / эквайринга (история операций)
4. **Считает юнит-экономику** — выручка, себестоимость, валовая прибыль, маржа % по каждой позиции
5. **Сверяет с контекстом** — инфляция, изменение себестоимости, отраслевые ориентиры, если есть данные
6. **Строит ценовые сценарии** — что будет с выручкой и маржой при +5%, +10%, +15%, используя историческую корреляцию там, где хватает данных
7. **Показывает анализ** — без рекомендации цены; решение остаётся за владельцем

Результат даёт владельцу основание принять собственное решение о цене — с реальными цифрами перед глазами.

---

## Как это работает

### Шаг 1 — Предварительная проверка

**Категория бизнеса:** если не ясно, к какой категории отнести бизнес для сверки с отраслевыми ориентирами, спросите прямо: «Для сверки с ориентирами по рынку нужна категория вашего бизнеса — розница, услуги, общепит, производство и т.д. Что у вас?»

**Источники данных:** отдельной предпроверки для CSV-выгрузок не требуется. Если данных из рабочей папки бизнеса не хватает (короткая история, части файлов нет) — отметьте это и продолжайте с тем, что есть; не блокируйте анализ целиком.

**Если выгрузок вообще нет:** предложите загрузить CSV — навык умеет работать от выгруженных данных по операциям и расходам. Ожидаемая схема — в `reference/csv-schema.md`.

### Шаг 2 — Уточнить объём анализа

Задайте владельцу два вопроса:

1. **«Какие товары или услуги разобрать?»**
   - Все, или конкретный список?
   - Если «все» — прежде чем тянуть всё подряд, убедитесь, что данных достаточно для осмысленного анализа.

2. **«Какая метрика важнее всего?»**
   - Валовая маржа (выручка минус прямая себестоимость)?
   - Чистая маржа (после всех расходов)?
   - Выручка на единицу?
   - Ответ определяет, как подавать результат.

### Шаг 3 — Забрать данные о себестоимости (банковская выписка / 1С)

Возьмите из выгрузки 1С или файла расходов в рабочей папке бизнеса:
- **Период:** последние 12 месяцев (или вся доступная история, если её меньше)
- **Извлечь:** себестоимость по товарной позиции/услуге, прямые расходы

Если такой выгрузки нет, спросите владельца:
- Разбивку себестоимости по позициям (материалы, труд, прямые расходы на доставку по каждой позиции)
- Известные изменения себестоимости за последние 6–12 месяцев

Если выгрузка есть, но себестоимость = 0 ₽ по всем периодам — не используйте 0 ₽ как входные данные. Прямо скажите владельцу:

> «В выгрузке не видно себестоимости за этот период. Чтобы посчитать осмысленную маржу, нужна разбивка расходов по товару или услуге — не одна средняя цифра на весь бизнес. По каждой позиции для анализа: во что она вам обходится? Материалы, прямой труд, любые прямые расходы на единицу. Подойдут даже приблизительные цифры.»

Отметьте это ограничение в разделе «Замечания по качеству данных» итогового вывода.

### Шаг 4 — Забрать данные о выручке (продажи 1С / ЮKassa / эквайринг)

Возьмите из выгрузки продаж 1С, ЮKassa или эквайринга (CSV из рабочей папки бизнеса):
- **Период:** тот же, что для себестоимости (последние 12 месяцев)
- **Извлечь:** сумма операции, товар/услуга, дата, количество (если есть)

Если ЮKassa/эквайринг покрывает только часть продаж (например, только онлайн-оплаты, без офлайн-кассы или наличных) — отметьте это ограничение в выводе.

Если доступен только один источник выручки — тоже отметьте ограничение.

### Шаг 5 — Посчитать юнит-экономику

По каждому товару/услуге в объёме анализа посчитайте:

| Метрика | Формула |
|---|---|
| **Выручка** | Сумма операций по позиции |
| **Себестоимость** | Данные из выгрузки или от владельца |
| **Валовая прибыль** | Выручка − Себестоимость |
| **Валовая маржа, %** | (Валовая прибыль ÷ Выручка) × 100 |
| **Продано, шт.** | Количество операций (если есть) |
| **Выручка на единицу** | Выручка ÷ Продано, шт. |
| **Себестоимость единицы** | Себестоимость ÷ Продано, шт. |

Отметьте любую позицию с маржой ниже 20% — не как рекомендацию, а как факт, достойный внимания владельца.

### Шаг 6 — Сверить с контекстом

Добавьте контекст, чтобы цифры были осмысленными:

- **Инфляция/рост себестоимости:** отметьте динамику затрат, если речь о росте закупочных цен. Пример: «Ваша себестоимость выросла примерно на X% за этот период, а цены не менялись — это сжало маржу на Y пунктов.»
- **Отраслевые ориентиры:** используйте категорию бизнеса, чтобы показать примерные ориентиры по валовой марже для ниши. См. `reference/industry-benchmarks.md`.
- **Историческое сравнение:** если есть 24+ месяцев данных, сравните маржу этого года с прошлым, чтобы показать направление тренда.

Аккуратно обрабатывайте нехватку данных: если операций меньше чем за 6 месяцев — не считайте раздел про эластичность, а отметьте: «Для оценки того, как объём реагирует на изменение цены, нужно минимум 6 месяцев истории продаж. Вместо этого покажу сценарный расчёт.»

### Шаг 7 — Ценовые сценарии

Постройте таблицу для каждого товара/услуги с тремя сценариями изменения цены:

| Сценарий | Новая цена | Прогноз выручки* | Валовая маржа, % |
|---|---|---|---|
| +5% | X ₽ | Y ₽ | Z% |
| +10% | X ₽ | Y ₽ | Z% |
| +15% | X ₽ | Y ₽ | Z% |

**Как считать прогноз выручки:**
- **Если есть 6+ месяцев истории:** оцените реакцию объёма по историческим данным. Если в прошлом уже было изменение цены, посчитайте наблюдаемую эластичность: `Эластичность = % изменения объёма ÷ % изменения цены`. Примените её для прогноза объёма при новой цене.
- **Если истории недостаточно:** покажите три предположения по объёму (−0%, −5%, −10%) и дайте владельцу самому выбрать реалистичный вариант.

Добавьте примечание: *«Это прогноз на основе доступных данных, а не гарантия. Реальная реакция объёма зависит от конкуренции, чувствительности клиентов и момента изменения цены.»*

### Шаг 8 — Показать анализ

Структурируйте вывод так: заголовок H2 с названием бизнеса и периодом,
затем четыре секции — таблица «Сводка по юнит-экономике» (товар/услуга,
выручка, себестоимость, валовая прибыль, маржа %), секция «Контекст и
ориентиры» (2–4 предложения про рост себестоимости, инфляцию, отраслевые
нормы), «Ценовые сценарии» (таблица сценариев по каждому товару, либо топ
3–5, если позиций много) и «Замечания по качеству данных» (отметьте любые
ограничения — частичные данные, отсутствие себестоимости, короткая
история).

Держите тон фактическим. Не пишите «вам стоит поднять цены» или «подумайте
о снижении цены». Владелец смотрит на данные, чтобы принять решение сам.

## Где проходит граница

**Этот навык показывает данные. Он не рекомендует цену.**

Если владелец спрашивает «так что мне делать?» — ответьте: «Могу показать, что подсказывают данные, но решение о цене — за вами. Хотите, смоделирую ещё какие-то сценарии?»

Это осознанное ограничение. У решений о цене есть реальные последствия для бизнеса, и они зависят от контекста, который знает только владелец (позиционирование среди конкурентов, отношения с клиентами, потребность в деньгах здесь и сейчас). Задача навыка — убедиться, что перед принятием решения владелец смотрит на реальные цифры, а не на догадки.
